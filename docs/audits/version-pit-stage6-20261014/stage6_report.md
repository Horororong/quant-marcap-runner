## 실패와 복구 범위

첫 CI `38592204895`는 원본 감사 아티팩트 복원 중 `HTTP Error 503: Egress is over the account limit.` / exit 1로 실패했다. DART 요청은 실행되지 않았다. 재시도하지 않고 같은 불변 release kit만 복원하는 별도 job으로 수집을 분리했다. `38592615003`에서 kit SHA/CRC/verify, 전용 Python 안전 테스트 및 원문 6건 수집이 성공했다. 해당 run의 기존 60건 전체 artifact 복원 job은 **SKIPPED**, 전수 재실행은 보존된 로컬 60건으로 완료했다. CI 성공을 60건 전체 복원 성공으로 표시하지 않았다.

로컬 첫 금융 재대조는 replay 종료를 기다리지 않아 `N01.json` 미생성 / FileNotFoundError / exit 1로 실패했다. 실패 로그를 보존하고 replay exit 0과 60파일 완료를 확인한 뒤 재대조했다. 데이터나 분모를 바꾸지 않았다.

GitHub 바이너리 blob 업로드 도구 두 번은 응답 없이 사용자에 의해 중단됐다. HTTP 상태·종료코드는 반환되지 않았다. 원격 ref는 수집 코드 커밋에 유지되었음을 확인했고 같은 도구를 반복하지 않았다. 원문 ZIP 자체와 Actions ZIP은 보존하고, 저장용 사본을 base64 텍스트로 전달했다. 복원 bytes의 기존 SHA·CRC를 다시 확인하여 감사 결과가 변하지 않음을 검증했다. `.zip.b64`는 전송 컨테이너이며 원본 공시를 수정한 것이 아니다.

그 후 단일 대용량 tree 게시도 45초 안에 응답하지 않아 중단했다. 그 tree의 예상 SHA `cea55292e34d3e4dad02bf87279a2667b4dc7f41`는 원격 GET에서 404였고 결과 commit/ref 업데이트는 실행하지 않았다. **최종 보고서·새 감사 코드·증거는 로컬 브랜치에만 완료**되어 있다. 원격 브랜치는 마지막 확인된 `c209a8f9b84a9de5afddbdcd4d3136d8533beb46` 수집 코드까지이며, 새 154개 테스트/PIT 감사의 GitHub CI와 추가 KRX 공개 페이지 Actions 조사는 **미검증/미실행**이다. 로컬 154개 실행 및 60건 독립 재검증과 구분한다. 현재 local commit의 정확한 tree를 작은 객체 단위 또는 승인된 Git 전송 경로로 같은 브랜치에 게시한 뒤 `[stage6-evidence]`에서 보존 원문 감사를 재현하면 된다. 기존 DART 수집 marker를 다시 실행할 필요는 없다.
