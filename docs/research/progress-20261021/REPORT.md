## 백필: 지금은 내부 정책으로 정체

실제 main의 코드·승인 config·실행 장부와 Actions 로그를 읽었다. main의 여섯 source owner 해시는 해당 main config와 모두 일치한다. main의 수정하지 않은 `check_recovery_gate` 함수 AST로 현재 상태를 평가한 결과 `ONCE_PER_KST_DAY`다. 전체 collector를 실행하거나 DART HTTP를 호출하지 않았다.

`ONCE_PER_KST_DAY`는 프로젝트의 KST 하루1회 정책이다. DART의 외부 사용량 제한 응답이 아니다. 외부 계정의 남은 호출량은 확인되지 않았으며 0HTTP 검사로 외부 한도를 추정하지 않았다.

마지막 성공 원문은 `20100331002054`, 저장 시각 UTC `2026-10-20T22:05:20.561506+00:00` / KST10/21 07:05:20이다. 과거57건의 성공 원문 응답은 입증됐지만, 당시 재시도 및 중단된2062의 HTTP 시도 수까지 정확히 집계할 공개 worker 로그는 확보하지 못했다. **과거 HTTP 총수를57로 단정하지 않는다. 이번 실제 HTTP는0이다.**

요청 전 `check_gate/check_recovery_gate`에서 차단되면 lease를 쓰기 전에 종료하므로 기회를 차감하지 않는다. 승인 해시/큐 precheck 실패도 run slot 생성 전이다(단, precheck HOLD는 남을 수 있다). HTTP 전에 durable lease를 생성한 실제 실행은 이후0건/실패여도 한 번으로 센다. 이는 승인된 무제한 실패 재시도 방지 정책이며 임의로 되돌리지 않는다. UTC→KST의 `astimezone` 및 장부 날짜에 오류 증거는 없었다.

현재 완료 접수번호157개, 예약200/300문서, 실행2/3회, 기존 예약의 pending43개다. `20100331002054`는 완료, `20100331002062`는 -15 종료 후 DEFERRED/미완료, `20100331002063`은 PENDING이다.2062의 이전 HTTP 시도 가능성과 원문 저장 완료를 혼동하지 않는다. 두 문서의 durable 완료 기록은 없다.

다음 일일 창은 KST `2026-10-22T00:00:00+09:00` / UTC `2026-10-21T15:00:00+00:00` 이후다. 날짜 경과는 실행 허가가 아니다. source hash·원문 검토·동시 실행·잔여 승인·외부 오류·장부를 다시 확인한 다음 아래 기존 경로를 사용한다.

```sh
gh workflow run backfill-dart-legacy-2000-2014.yml \
  --repo Horororong/quant-marcap-runner --ref main \
```

이 명령을 이번에 실행하지 않았다. 두 문서 segment는 마지막 승인 실행 슬롯을 사용한다. 그 뒤 남은41문서를 위한 다음 실행/실제 재실행은 새로운 유한 예산 승인이 필요하다. 300문서 예약 여유가 실행 횟수 추가 승인은 아니다. 문서2건과 HTTP2요청도 동일한 개념이 아니다(기존 worker는 문서당 최대2요청). 향후 실제 시험에서는 progress의 요청·응답을 별도로 집계해야 한다.

예약 cron은05:17KST로 존재한다. 실제 최근 예약은 지연되어08:10KST에 실행됐고 로그는 NO_COLLECTION이었다. 자동 예약에는 `resume_parent_run`이 없으므로 HOLD를 자동 복구하지 않는다. 미래 예약을 수집 재개 완료로 보고하지 않는다. 기존 시간 admission/체크포인트/강제중단 회귀는 ba26 CI에서 통과했지만 실제 수정 후 HTTP 재개는 아직 미입증이다.

별도 메타데이터 관찰: 동결된 큐의2009.12 보고서 `period_end=2009-12-01`과 실제 추출행의 원문 결산일은 다르다. 확인한02054의 실제 행은 원문 header 근거 `2009-12-31`이다. 큐의 월 단위 메타를 재무 결산일/PIT 근거로 사용하면 안 된다. 동결 selection/hash는 수정하지 않았다. 다음 두 원문은 아직 확보되지 않았으므로 실제 기간은 미검증이다. 이는 KST 일일 제한 날짜와 별개다.

## 이번 사용자 기능 증가: 결과 비교 저장·재열기

별도 개발 브랜치 `feat/saved-comparisons-20261021`는 게시된 ba26에서 시작했다. 원본/최소 복원/운영 main/기존 통합 결과를 변경하지 않았다. 기존 규칙 기반 한국어→확인 DSL→공통 엔진→CURRENT→조건 변경 흐름 위에 **이름 붙인 비교 저장과 재열기**를 추가했다.

- 성공한2~6개 실행만 저장한다. 실행 순서, fingerprint, 기간, 저장 실행의 데이터·비용·버전 provenance와 실행별7개 파일(전략 snapshot/preflight/status/NAV/성과CSV/CURRENT HTML/manifest)의 SHA256을 기록한다.
- 재열기 시 저장 원본을 확인한다. 원본 누락·변경·실패 상태·중복 ID는 거부하고 기존 비교를 덮어쓰지 않는다. 현재 편집기의 조건이나 client가 보낸 성과로 대체하지 않는다. 같은 이름의 새 저장도 새 ID다.
- 새 지표 산식/엔진은 없다. 기존 CURRENT의 성장·로그배수·낙폭 차트와 성과표/기간·비용 선택을 그대로 연다. 현재 웹의 기본 보고는 요청 전체 `longest` 한 기간이다. 차트 zoom은 성과 재계산이 아니며 선택 기간/zoom 자체는 이번 저장 범위가 아니다.
- 실제 KRX2024의 기존 검증된 수수료1.5bp/2.5bp 두 실행을 새 시험 폴더로 복사해 사용했다. 원본 및 복사본52파일은 그대로다. 브라우저에서 비교→저장→페이지 새로고침→재열기→세 차트/로그축/비용 선택이 통과했고 서버 재시작 후 같은 record 재열기도 통과했다. 기존 엔진 실행이나130파일 전체 회귀를 반복하지 않았다.
- 관련18시험 PASS(기존 언어6+웹6+새 비교 경계6), 실제 브라우저/서버 재시작 PASS, JS 문법 및 생성 DSL 계약 PASS. 첫 브라우저 시도는 sandbox 소켓 권한 문제, 다음 시도는 시험이 CURRENT의 비용 option을 `fixed_cost`로 잘못 지정한 문제였다. loopback 허용 환경에서 실제 계약값 `net:fixed_cost`로 수정 후 통과했다. 제품 성과 기대값을 바꾸지 않았다.
- 이 새 기능은 **로컬 검증 완료·원격 CI 미실행** 상태다. 이번 공개 승인은 ba26의20파일에 한정된다. 새 기능/인계 증분은 게시하지 않았고 새 증분 manifest에 구체화한다. ba26의 성공을 새 기능 최종 커밋의 CI로 인용하지 않는다.

실제 보존 결과의 fixed_cost Net 최종배수는1.5bp에서0.6814033333333344,2.5bp에서0.6813351282051288이다. 이는 기존 CURRENT CSV를 읽은 값이며 이번 재계산이 아니다.2024 사례는 경과365일 미만이므로 CAGR가 비어 있는 기존 계약을 유지한다. MDD/Sharpe와 성장/로그/낙폭은 해당 CURRENT의 표본 조건대로 표시한다.

## 보존과 재개

변경된 코드·새 증거만 새 증분에 보존한다. ba26/기존 감사 원문 증분은 원격 Git에 있고 v5 전달은 이미 완료했다. v7/v8 ZIP·복구 bundle·backup-only metadata는 연구 브랜치 게시와 다른 객체로서 여전히 로컬 보존이다. 이번 새 기능 커밋/새 비교 record와 두 실행의 해시 바인딩 원본도 새 로컬 증분에 보존하며 원격에 업로드했다고 주장하지 않는다. 원본 없이 원격만의 전체 복원 시험은 여전히 미실시다. 과거12 envelope의 상세 비교 미검증도 유지한다.

새 세션 실행/검증 명령은 [RESUME.md](RESUME.md), 실제 메타데이터는 같은 디렉터리의 JSON/log를 따른다. 환경 복원, source 의미 판정, 금융/PIT 인증, 연구 목표 달성은 서로 다른 완료 상태다.
