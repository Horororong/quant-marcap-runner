# Source-only 자료의 실제 신호 준비도와 장기 공통 차단

원문→숫자→공개일→공식 거래일→당시 종목 연결→특정 공개 본문 버전→B/P 산술을
실제2010-04-30에서 대조했다. 사조산업007160의 **OFS equity 한 필드**는 그
신호일에 한정한 연구 자료 준비도를 충족한다. 이는 전체 문서·모집단·정정 역사·
투자 인증이 아니다. 고려반도체089890은 축약 회사명/정확한 본문 버전 연결이
미인증이다. 기존 운영 provider와 투자 게이트를 우회하지 않았다.

**장기 다종목 신규 완주0, 실제 기업행위 차단 해소0**다. 기존 전체 예정경로의
10,136기록/9,926중복제거 증상을 재현했고5,258개의 종목·진단원인별 조사 작업으로
묶었다. 반복 조사량을 압축한 것으로 미해결 사건을 해결했다고 세지 않는다.

### 인증 범위와 as-of 경계

3월31일 다음 **민간 달력일**4월1일에 실제 공식 거래가 있으므로 이 공개일의
첫 다음 거래일을 증명한다. 주말/휴일 추정이나 전체2010년 달력 인증이 아니다.
4월30일 신호 거래일은 별도 공식 응답으로 입증한다. 공개 당일은 사용 금지이며
신호 종가와 실제 주문 체결일은 동일하다고 가정하지 않는다.

사조의 원문 header AREGCIK00124799/사조산업주식회사와 당시 KRX007160/사조산업은
법인형태 표기만 제거해 정확히 일치한다. 이 특정 신호의 연결 근거이며 전체기간
사명/합병 계보가 아니다. 고려반도체시스템과 KRX축약명 고려반도체는 현재 API의
089890/코세스만으로 역사적 법인 연결을 자동 인증하지 않는다.

사조는 공식 family의 명시적 부모 접수번호·본문 docID/node와 직접 받아 대조한
재무표를 연결했다. last_reprt_at=N의20100301–20100501 전1페이지에서 해당
FY2009 사업보고서 후보가 하나이며, 늦은 CFS는 명시적으로 별도 첨부다.
따라서 **그 신호 이전 이용할 수 있는 특정 원본문 필드 선택**만 PASS다.
제목 유사성으로 새 정정 체인을 합치거나 전 역사에 정정이 없다고 선언하지 않는다.
record_attestations.json의 scope/asof_closed_through=2010-04-30,
full_correction_history_certified=false를 유지한다.5월3일은 이 검토 범위 밖이므로
동일 attestation을 재사용하면 UNVERIFIED로 차단된다. 투자0/6은 그대로다.

실제 경계 시험은 원본문3/31 당일 FAIL,4/30 as-of 필드 PASS,검토종료 뒤5/3
UNVERIFIED,늦은 CFS4/29·4/30사용 FAIL이다. CFS의 원문4필드는 여전히 미추출/
member-dcm직접연결 미인증이며5/3이 실제 첫 이용일이라고 가정하지 않는다.
정정 직전/이후·같은 날 정정의 버전 순서/불명확한 최신값에서 과거값으로 돌아가지
않는 경계는 별도 합성 시험이며 실제 정정 사례의 인증으로 세지 않는다.
공개 **시각**은 모두 UNVERIFIED다. backtest_eligible=False와 운영 게이트는 불변이다.

## 공통 기능과 전체 진단

-financial_record_readiness: 정확성·공개일·버전·역사 연결·신호 가용성을 필드별로
분리한다. 값/단위/issuer/member가 바뀌면 attestation 바인딩이 무효다. 최신
정정본이 불명확하면 과거 정상값으로 fallback하지 않는다. 소스 검토 성공과
계좌/투자 승인은 별도다. 금융 검증 공통 파일은 main 최소 PR와 동일 bytes다.

옮겼다. 기존 provider의 coverage_report와 PIT/raw-quarter 경로를 유지한다.
진단이 다른 B/P 계산기를 만들거나 운영 우회를 만들지 않는다. 기존 실제 DART
E2E의2020-04/10 결과와 source snapshot/계정선택 회귀가 통과했다.

겹치는 구간으로 묶고 전략·분위 노출을 보존한다. 같은종목의 다른 날 가격 점프를
하나의 기업행위로 합치지 않는다. preflight와 readiness_incidents 두 envelope가
같은 증상을 담으면 이중 집계하지 않는다. 실제 CLI 시험에서21→42가 되던 신규
연결 오류를 발견해 수정하고 회귀를 추가했으며, 수정 후21로 정확히 재현했다.
