# Quant Data Pipeline

## Purpose

This repository is the user's reproducible quant research data workspace. The design goal is point-in-time-safe data collection first, then factor calculation and backtesting.

## Automated schedule

- GitHub Actions workflow: `.github/workflows/update-quant-data.yml`
- Scheduled: 07:30 KST, Monday-Friday
- Manual run: Actions > Update quant data > Run workflow

## DART financial statements

Generated by `update_dart_financials.py`.

The script requires a GitHub repository secret named `DART_API_KEY`.

### Add the secret

Repository > Settings > Secrets and variables > Actions > New repository secret

- Name: `DART_API_KEY`
- Secret: your OpenDART API key

The API key must never be committed to a CSV, Python file, README or workflow file.

### Current DART design

- Downloads the OpenDART corporation-code master
- Maps DART `corp_code` to current KRX `stock_code`
- Uses filing receipt number to preserve a filing-date field
- Pulls consolidated (`CFS`) full financial statements
- Recent years only for routine daily CI
- Default daily company cap: 300

Optional repository variable:

- `DART_MAX_COMPANIES`: increase/decrease the daily company limit

Files:
- `data/financials/corp_master.csv`
- `data/financials/dart_full_financial_statements_recent.csv`
- `data/financials/dart_errors.csv`
- `data/status/dart_status.csv`

## Existing KRX point-in-time panel

The existing `marcap` workflow remains the base price/universe layer because it contains historical daily cross-sections, including securities that subsequently disappeared from the market.

For backtests, do not replace historical universe membership with today's KRX listing.

## Research rules

1. Signal inputs must only use information available on the signal date.
2. Financial data must be lagged to the actual filing date, not fiscal-period end.
3. Same-close signal and execution are prohibited unless the information was available before that close.
4. Delisted/disappeared securities cannot be silently dropped.
5. Transaction costs and liquidity constraints must be applied before strategy adoption.
6. Any crawler/API failure is logged rather than silently forward-filled.
